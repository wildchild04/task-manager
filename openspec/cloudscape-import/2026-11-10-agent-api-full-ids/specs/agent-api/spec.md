## MODIFIED Requirements

### Requirement: Lean responses
Responses SHALL contain only the fields each function documents. Lists SHALL return at most `limit` items (default 10 unless a function says otherwise, at most 50), with `more: true` and a `cursor` when there are more. Markdown texts SHALL be cut at `maxChars` characters (default 2000, at most 20000), with `more: true` and the `offset` to continue from. IDs SHALL be returned as their first 8 characters; requests SHALL accept a full ID or any prefix of at least 6 characters that matches exactly one item, and answer an ambiguous prefix with status 409. So an agent can build a web link to a page, `GET projects`, `GET tasks` and `GET task/:id` SHALL also return full IDs: each project and task SHALL carry its `fullId`, and `GET task/:id` SHALL carry its project's full ID as `projectFullId`, alongside the short forms. Errors SHALL be `{ error: { code, message } }` with a matching status.

#### Scenario: Paging a list
- **WHEN** a project has 25 tasks and `list_tasks` is called with `limit` 10
- **THEN** 10 tasks come back with `more: true` and a `cursor`, and calling again with that cursor returns the next 10

#### Scenario: Long description
- **WHEN** a task description is 5000 characters of Markdown and it is read with the defaults
- **THEN** the first 2000 characters come back with `more: true` and `offset: 2000`

#### Scenario: Short IDs
- **WHEN** a task is listed and then fetched by the 8-character ID from the list
- **THEN** the task is found

#### Scenario: Full IDs for links
- **WHEN** a task is fetched with `get_task`
- **THEN** it carries `fullId`, its full ID, and `projectFullId`, its project's full ID, alongside the short `id` and `project`, and `list_projects` and `list_tasks` carry each item's `fullId`

#### Scenario: Projects with their modes

- **WHEN** an agent lists projects with Personal container "Garden" and sub-project "Editor" of Project work container "Taskhub"
- **THEN** it gets "Garden" with mode `personal`, "Taskhub" with mode `project`, and "Editor" with mode `project` and parent Taskhub's ID

#### Scenario: A work loop

- **WHEN** an agent lists to-do work, gets one task, reads its description, starts it, comments and completes it
- **THEN** each call returns only its listed fields, and the task's history and comments show the agent's name

#### Scenario: Own suggestions

- **WHEN** "planner" suggests an insert on a task's description and a tombstone of an exploration, and "reviewer" suggests something else
- **THEN** `GET suggestions` as "planner" returns its two, the tombstone first, and with `status: "pending"` only the pending ones

#### Scenario: Paging search results

- **WHEN** three pages match "plan" and an agent searches with `limit: 2`
- **THEN** it gets two with `more: true` and a `cursor`, and the next call with that cursor gets the third
